# Second Opinion for Vision Inspection

AI second opinion for camera inspection on production lines.
Inline inspection cameras are tuned never to miss a defect, so they also reject good products, which end up as waste.
This tool re-checks the rejected items, sorts them (likely good, uncertain, defect confirmed) and shows a heatmap of where it sees a problem.
It never releases an item on its own: a person approves every recovery.

Group project for "Building an Impactful Tech Product", Tomorrow University, November 2026.
The report and the user test results are part of the group submission.

## Repository map

| Folder | What it holds |
|---|---|
| `scripts/` | Model comparison: about 20 anomaly detection models on VisA, MVTec AD and GoodsAD, same folds and escape rule |
| `evaluation/` | One evaluation for every model, from score files; the escape rule and its check |
| `reference_prototype/` | The MVP: PatchCore-style model, three-way decision, review app used in the user tests, user test analysis |
| `docs/results.md` | All model results (generated by `scripts/lane.py`) |
| `shared/` | Per-item score files shared between the folders |

## Version used in the user tests

The round 2 user tests (16 Nov 2026) ran on commit `e6b6f87`:
`reference_prototype/app.py`, with the planted items in `reference_prototype/results/bottle`.

```bash
cd reference_prototype
pip install -r requirements.txt
python run_pipeline.py --data-root data/mvtec --category bottle --coreset-ratio 0.01 --out results/bottle
streamlit run app.py -- --results results/bottle
```

`run_pipeline.py` needs the MVTec AD bottle images (see `reference_prototype/README.md`) and writes the
two test sets into `results/bottle`, next to the planted items that are already committed.

## Model comparison

Datasets are not committed. `data/` is ignored by git.

```bash
pip install torch torchvision   # pick the build for your GPU
pip install -r requirements.txt
python scripts/download.py visa
python scripts/run.py visa candle patchcore
```

Prints recovery of good items at 0, 1 and 5 percent escape of true defects,
plus AUROC for reference. Results land in `results/` as JSON.
